# 설계 및 정책

이 문서는 `speech-kws-rag` 프로젝트의 핵심 설계 원칙, 기술적 결정, 개발 및 운영 정책을 다루는 **Single Source of Truth (SSOT)** 입니다.

## 1. 목표 및 비전

**목표:** 10–20초 길이의 음성 스트림에서 실시간으로 보험 도메인 관련 핵심 키워드(100–200개)를 정확하게 검출(top-k)하는 것을 목표로 합니다.

**비전:** 기존 STT/NLU 파이프라인의 한계를 넘어, 오디오 신호에서 직접 키워드를 추출하여 지연 시간을 줄이고 บริบท에 맞는 키워드 검출 성능을 극대화합니다. 최종적으로는 상담 분석, 실시간 보조, 교육 등 다양한 다운스트림 태스크의 기반 기술로 활용될 수 있습니다.

## 2. 핵심 아키텍처

이 프로젝트는 **ColBERT 스타일의 late-interaction** 아키텍처를 채택하여 오디오와 텍스트 간의 세밀한 정렬을 수행합니다.

### 2.1. 주요 구성 요소

1.  **Keyword Token Bank (텍스트 측):**
    *   **내용:** 검출 대상인 모든 키워드(캐노니컬 형태)를 미리 토큰화하여 임베딩을 저장해 둔 "은행".
    *   **인코더:** `E5-multilingual`와 같은 강력한 다국어 텍스트 인코더를 사용하며, **학습 내내 동결(frozen)**됩니다.
    *   **구축:** 각 키워드를 1) 그대로 토큰화하거나, 2) `"이것은 {키워드}입니다"`와 같은 마이크로 템플릿에 넣어 토큰화한 후, `{키워드}`에 해당하는 부분의 서브토큰 임베딩만 추출하여 저장합니다. (후자가 안정적)
    *   **IDF 가중치:** 토큰 뱅크의 모든 토큰 `t`에 대해 "해당 토큰이 등장하는 키워드 수"인 `df(t)`를 계산하고, 이를 이용해 IDF(Inverse Document Frequency) 가중치를 부여합니다. 이를 통해 "보험", "고객"처럼 자주 등장하는 범용 토큰의 영향력을 줄입니다.
        *   **계산식:** `idf(t) = log((N+1) / (df(t)+1))` (N: 전체 키워드 수)
        *   **저장 형태:** 계산된 가중치는 각 토큰과 함께 토큰 뱅크에 저장됩니다.
          ```json
          {
            "term_id": "손해보험",
            "tokens": [
              {"string":" 손해","proto":[...768...],"weight":1.00},
              {"string":" 보험","proto":[...768...],"weight":0.38}
            ],
            "jamo_tokens":[
              {"string":"ㅅㅗㄴㅎㅐ","proto":[...],"weight":0.95},
              {"string":"ㅂㅗㅎㅗㅁ","proto":[...],"weight":0.45}
            ]
          }
          ```

2.  **Audio Encoder (오디오 측):**
    *   **모델:** `Whisper`, `WavLM` 등 사전 학습된 강력한 오디오 인코더를 기반으로 합니다.
    *   **MLP 어댑터:** 오디오 인코더 위에 작은 MLP(Multi-Layer Perceptron) 어댑터를 추가하여, 오디오 프레임 임베딩을 텍스트 토큰 임베딩과 같은 공간으로 정렬(align)합니다. **학습 시에는 이 어댑터와 오디오 인코더의 마지막 일부 블록만 학습**됩니다.

### 2.2. 학습 및 추론 과정

**핵심 원칙:** 모델은 문장 텍스트를 직접 입력으로 받지 않습니다. 오디오 신호만 인코딩하고, 라벨(정답 키워드)은 학습 시 손실 계산에만 사용됩니다.

**1) 데이터 준비 (Data Preparation)**
*   `train.jsonl`의 각 샘플은 `wav_path`와 `text` (선택 사항)를 가집니다.
*   전처리 단계에서 `text` 필드에 `glossary.jsonl`에 정의된 키워드의 캐노니컬 표현이 포함되어 있는지 확인합니다.
*   포함된 모든 키워드의 `term_id`를 해당 샘플의 `positives` 리스트 (멀티라벨)로 저장합니다. `text` 필드는 이 라벨링 과정을 자동화하기 위한 편의 기능입니다.

**2) 학습 (Training)**
*   **미니배치 구성:**
    *   입력: `B`개의 오디오 샘플 (`wav`)과 각 샘플의 정답 라벨(`positives`).
    *   후보 키워드 집합 `K`: 각 샘플의 `positives`와 샘플링된 `negatives`의 합집합. "보험자"↔"피보험자"와 같은 **하드 네거티브**를 반드시 포함하여 모델이 미세한 차이를 배우도록 합니다.
*   **전방 계산 (Forward Pass):**
    1.  **오디오 인코딩:** Audio Encoder는 오디오 샘플을 프레임 단위 임베딩 시퀀스 `A = {a_i}` (i=1..F)로 변환합니다. (L2 정규화 적용)
    2.  **키워드 로딩:** 후보 키워드 `k`에 대해, 토큰 뱅크에서 토큰 임베딩 시퀀스 `T_k = {t_{k,j}}`와 IDF 가중치 `w_{k,j}`를 가져옵니다.
    3.  **Late-Interaction 점수 계산:** ColBERT 스타일의 상호작용 점수를 계산합니다.
        `s_k = max_{i≤F, j≤L_k} (cos(a_i, t_{k,j}) ⋅ w_{k,j})`
        이는 모든 오디오 프레임과 모든 키워드 토큰 간의 가중 코사인 유사도 중 최댓값을 취하는 방식입니다.
*   **손실 계산 (Loss Calculation):**
    *   멀티라벨 BCE Loss를 사용합니다. 점수 `s_k`에 스케일링 파라미터 `α`, `γ`를 적용하여 손실을 계산합니다.
    *   **양성 샘플 (k ∈ P):** `-log(σ(α(s_k - γ)))`
    *   **음성 샘플 (k ∈ N):** `-log(1 - σ(α(s_k - γ)))`
    *   (시작값 예시: `α=8, γ=0.1`)
*   **파라미터 업데이트:** 계산된 손실을 바탕으로 오디오 인코더의 MLP 어댑터 (및 선택적으로 인코더 일부)의 가중치를 업데이트합니다. 텍스트 인코더와 토큰 뱅크는 동결 상태를 유지합니다.

**3) 추론 (Inference)**
*   입력 오디오(10–20초)를 0.8초 창(window) / 0.2초 이동(hop) 간격으로 나눕니다.
*   각 창에 대해, **모든 키워드(100–200개)**를 후보로 하여 점수 `s_k`를 계산합니다.
*   점수가 가장 높은 top-k 키워드를 해당 창의 결과로 반환합니다.
*   (선택) 창 간의 결과를 EMA(Exponential Moving Average) 또는 다수결(majority vote) 방식으로 스무딩하여 최종 결과를 안정화합니다.

## 3. 정책 및 규칙

### 3.1. 브랜치 전략

*   `main`: 프로덕션 릴리즈 브랜치.
*   `dev`: 다음 릴리즈를 위한 통합 브랜치.
*   `feat/{issue-number}-{description}`: 기능 개발 브랜치.
*   `fix/{issue-number}-{description}`: 버그 수정 브랜치.
*   `exp/{yyyymmdd}-{initials}-{idea}`: 실험/POC 브랜치.

### 3.2. 커밋 메시지

[Conventional Commits](https://www.conventionalcommits.org/) 스타일을 따릅니다.
*   `feat`: 새로운 기능 추가
*   `fix`: 버그 수정
*   `docs`: 문서 변경
*   `style`: 코드 스타일 변경 (포맷팅, 세미콜론 등)
*   `refactor`: 기능 변경 없는 코드 리팩토링
*   `test`: 테스트 코드 추가/수정
*   `chore`: 빌드, 패키지 매니저 등 기타 변경

### 3.3. 코드 스타일

*   `black`, `isort`, `ruff`를 사용하여 코드 스타일을 강제합니다. (`pyproject.toml` 설정 참고)
*   `pre-commit` 훅을 사용하여 커밋 전에 자동으로 포맷팅 및 린트를 수행합니다.

## 4. 리스크 및 완화 방안

*   **과적합(Overfitting):**
    *   **리스크:** 소량의 학습 데이터로 인해 특정 발화 패턴이나 노이즈에 과적합될 수 있습니다.
    *   **완화:** Data augmentation (배경 소음, 속도 조절), MLP 어댑터의 dropout 비율 조절, 오디오 인코더의 동결 레이어 수 증가.
*   **OOK (Out-of-Keyword) 문제:**
    *   **리스크:** 정의되지 않은 키워드에 대해 모델이 높은 점수를 반환할 수 있습니다.
    *   **완화:** 학습 시 다양한 "쓰레기" 음성(키워드 미포함)을 네거티브 샘플로 활용, 추론 시 점수 임계값(threshold) 튜닝.

*   **검색 성능:** R@k (Recall at k), MRR/MAP
*   **오탐지율:** Hard-Confusable FPR (혼동하기 쉬운 키워드에 대한 거짓 양성 비율)
*   **속도/안정성:** Noisy/Fast Δ (노이즈/빠른 발화 환경에서의 성능 변화), 창당 지연 시간 (ms)
